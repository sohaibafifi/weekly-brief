# Weekly Brief

Sunday-evening agent that fetches your IMAP mail and ICS calendars, then prepares the upcoming week as:

- **Static HTML dashboard** (`~/Documents/WeeklyBrief/<isoyear>-W<wk>/index.html`)
- **Markdown file** (`brief.md`)
- **Email digest** sent to yourself

The brief contains: events grouped by category (color-coded per source calendar), a Mon→Sun grid with computed free slots within your work hours, mail that needs attention (flagged, VIPs, threads awaiting your reply), and per-meeting prep notes generated by Mistral.

## Stack

- Python ≥ 3.11, managed via `uv`
- IMAP via `imap-tools` · ICS via `icalendar` + `recurring-ical-events`
- Jinja2 templates · Tailwind via CDN (zero build step)
- Mistral chat completions for narrative + per-meeting prep
- macOS `launchd` for Sunday 18:00 trigger

## First-time setup

```bash
cd ~/Codes/VP/Assistant
uv sync
cp .env.example .env                 # fill IMAP_PWD, SMTP_PWD, MISTRAL_API_KEY
cp config.example.yaml config.yaml   # fill IMAP/SMTP hosts, ICS URLs, VIPs
```

## Manual run

```bash
uv run weekly-brief preview            # build, no email, opens browser
uv run weekly-brief run                # build + email
uv run weekly-brief run --no-email     # build + write files only
uv run weekly-brief run --week current # current week (default: next)
```

## Notion integration (optional)

Each Sunday run also publishes the brief as a row in a Notion database. To enable:

1. Visit https://www.notion.so/profile/integrations → **New internal integration** → copy the secret token into `NOTION_API_KEY`.
2. Create a Notion database with at least a **Title** column and a **Date** column.
3. On the database, click **…** → **Connections** → add your integration so it can write.
4. Copy the database ID from its URL (the 32-char hex string before `?v=…`).
5. Edit `config.yaml`:
   ```yaml
   notion:
     enabled: true
     database_id: "abc123…"
     title_prop: Name      # exact column label
     week_prop: Week       # exact date-column label (or "" to skip)
   ```
6. `uv run weekly-brief test-notion` to verify.

Behaviour: each weekly run finds an existing row titled `Brief <ISO-week>`. If found → in-place update (archive old blocks, write fresh ones). If not → create new row. No duplicates.

## Schedule (macOS launchd, Sunday 18:00)

```bash
bash ops/install.sh
# Edit ~/.config/weekly-brief/secrets.env and fill in IMAP_PWD / SMTP_PWD / MISTRAL_API_KEY
launchctl kickstart -k gui/$UID/com.sohaibafifi.weekly-brief    # run now (test)
```

Logs land in `~/Library/Logs/weekly-brief.{out,err}.log`.

To uninstall:
```bash
launchctl bootout gui/$UID/com.sohaibafifi.weekly-brief
rm ~/Library/LaunchAgents/com.sohaibafifi.weekly-brief.plist
```

## Config reference

See `config.example.yaml`. Each calendar entry has `name`, `category` (e.g. `work`, `personal`, `family`), and either:

- `url:` — a single ICS URL, **or**
- `urls:` — a list of ICS URLs all rolled into the same category. Each feed appears in the meeting-prep block as `<name> #1`, `<name> #2`, …

You can also list several entries with the same `category` if you want each feed to have its own meaningful name (e.g. `Family` + `Kids school`, both `category: family`).

VIP entries can be plain emails or domains prefixed with `@`. Work hours per weekday are arbitrary intervals; weekends omitted = no free-slot computation there.
